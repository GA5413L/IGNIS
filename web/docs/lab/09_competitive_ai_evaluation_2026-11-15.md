# Competitor AI and evaluation evidence, 15 November 2026

## Decision

These are credible competitors with different strengths, not a set of interchangeable chat demos. The other Emberfall has broader literature retrieval and a published retrieval-baseline comparison; Entropy exposes quote-traced live extraction; StarryNight has broad conversational workflows and a saved mixed AI/template evaluation; PYRION publishes unusually detailed adversarial repair and fallback audits; Flamefall Analytics publishes grouped, unseen-fuel and calibration results and withdraws a failed solid model. IGNIS should borrow their measurable practices and compare matched user tasks. None of the evidence below establishes an overall winner or predictive-physics SOTA.

IGNIS currently has 243 passing offline tests and 17 passing browser tests, with one intentional duplicate skipped. Its current live semantic comparison is **NOT RUN**, and no interpretation configuration is accepted. Those tests establish bounded software behavior, not better language answers or predictive accuracy. Current strengths are inspectable condition comparisons, explicit unknowns, detector denominators and source-preserving exports; current deficits include live source ingestion, broad literature Q&A and evaluated learned predictions. See [local verification](../LOCAL_VERIFICATION_2026-11-15.md).

## 1. StarryNight: useful mixed-mode evaluation, limited semantic gold

The saved report dated **14 November, 00:51** has all 26 question IDs: 16 `ai`, 10 `template`. Assistant recount confirms **19/23 fact checks**, **22/23 citation checks**, **3/3 required refusals**, **3/3 required insufficient-data responses**, and zero flagged probability-language violations. Five of the 23 citation targets are empty arrays; restricting to nonempty expected-source targets gives **17/18**, not 22/23. The report also records two number-validator failure events. These are disclosed failures, not hidden by an all-pass headline. [Saved report](https://github.com/G3hamza/astrofire/blob/a524b474fff0c54db59f47d5e2d079e4663506c2/ai/eval/report.md), [question set](https://github.com/G3hamza/astrofire/blob/a524b474fff0c54db59f47d5e2d079e4663506c2/ai/eval/questions.jsonl).

The scorer requires expected substrings somewhere in answer/findings/interpretation and expected investigation IDs or acronyms in evidence cards. It does not adjudicate claim-to-citation entailment or the page supporting a claim. Substring matching can reject a correct paraphrase and accept a wrong answer containing the expected phrase. The three off-topic/injection cases are a small negative sample, and no sealed holdout or external reviewer is documented in this artifact. Full generated answers and per-request model/token receipts are absent from the report, limiting retrospective adjudication. [Scorer](https://github.com/G3hamza/astrofire/blob/a524b474fff0c54db59f47d5e2d079e4663506c2/ai/eval/run.py).

The configured default is Groq `openai/gpt-oss-120b`, with optional provider/model fallbacks; these are literal source settings, not a check of current availability. No-key operation uses deterministic templates. Failed checks can trigger a regeneration and then template fallback. Retrieval combines BM25 with expansion, with optional pre-existing local embeddings and reciprocal-rank fusion. This is a broader interaction system than IGNIS currently demonstrates, and its source separates model narration from structured evidence. The saved result does not pin the effective retrieval/provider configuration per row. [Configuration](https://github.com/G3hamza/astrofire/blob/a524b474fff0c54db59f47d5e2d079e4663506c2/ai/config.py), [LLM chain](https://github.com/G3hamza/astrofire/blob/a524b474fff0c54db59f47d5e2d079e4663506c2/ai/llm.py), [chat](https://github.com/G3hamza/astrofire/blob/a524b474fff0c54db59f47d5e2d079e4663506c2/ai/chat.py), [retrieval](https://github.com/G3hamza/astrofire/blob/a524b474fff0c54db59f47d5e2d079e4663506c2/ai/retrieval.py).

Its numeric guard builds a shared set of numbers from evidence and the question, permits rounded/unit-converted variants and tolerances, and checks generated numbers against that set. This reduces some fabrication but does not bind a number to its experiment, variable or measurement window. A correct-looking value could still be assigned to the wrong case. Known-ID citation filtering similarly cannot prove a supported statement. The proper adoption is a regression guard plus per-claim source binding, not a claim of impossible hallucination. [Guardrails](https://github.com/G3hamza/astrofire/blob/a524b474fff0c54db59f47d5e2d079e4663506c2/ai/guardrails.py).

The result is useful: reranking improves hit@5 while reducing hit@1/MRR relative to hybrid, so there is no uniform ranking winner. The evaluator retrieves passages and then deduplicates paper IDs, so a top-ten passage list need not contain ten distinct papers. Such gold tests topical retrieval more than exact support for an engineering claim. The negative questions are clearly off-domain, not difficult in-domain unknowns. The result's extraction-label section is `null`; a provided labeling workflow is not a completed human-labeled extraction evaluation. The support score is lexical overlap, including six-character word-prefix matches, not entailment. A synthetic, source-reviewed counterexample is a cited claim that a flame-spread rate increased versus a passage saying it **did not increase**: all retained content-word prefixes match, producing overlap 1. This is an assistant calculation of the metric's limitation, **not an observed generated answer**. Confidence is a weighted combination of overlap, citation share, flight evidence and paper count, not calibrated probability of truth. [Answer/scoring implementation](https://github.com/0xdevabir/runtime-terrors/blob/a42561939e97a1b1738dee9e8ec54a13341aee74/backend/app/answer.py).

There is also a current source-contract discrepancy worth testing before adoption: the README says unsupported/invalidly cited sentences are dropped, but the inspected answer path emits the answer text and later reports diagnostics; the frontend retains the text and marks invalid citation chips. The Ask page describes invalid citations as removed. No statement-removal stage was found in this path. This is a static implementation finding, not a live reproduction. [README](https://github.com/0xdevabir/runtime-terrors/blob/a42561939e97a1b1738dee9e8ec54a13341aee74/README.md), [answer rendering](https://github.com/0xdevabir/runtime-terrors/blob/a42561939e97a1b1738dee9e8ec54a13341aee74/web/src/components/Answer.tsx), [Ask page](https://github.com/0xdevabir/runtime-terrors/blob/a42561939e97a1b1738dee9e8ec54a13341aee74/web/src/app/ask/page.tsx).

Credit the breadth: the project supports literature Q&A, personas, mission briefs and provider fallbacks, and publishes more informative retrieval ablations than IGNIS presently has. Configured providers include Anthropic, Gemini and Groq, with extractive fallback after exhaustion; saved extractive metrics do not establish their generative performance. Corpus-size claims in its README were not independently recounted in this specialist review. ## 4. PYRION: detailed repairs and bounded narration, with residual limits

PYRION's phase-one audit records failures, repairs and repeated checks through four rounds. Its use of independent means a separately run reviewing agent; it does not claim NASA validation or independent combustion-expert review. Earlier observed defects that later rounds close must not be presented as current defects. The final audit reports 59/59 web and 166/166 engine tests, plus selected live provider/fallback checks. These are author-published results, not reruns by this team. [Audit history](https://github.com/Lucyyngceo/pyrion/blob/f642df5b9a8279fb613830a924fee97129a3e916/validation/reports/phase1-llm-audit.md).

The current design has substantive controls: parse written quantities without silently supplying missing axes; keep suggestions separate; recompute the comparison on the server; use deterministic verdict/count text; limit optional model prose to target context; record routing/fallback metadata. OpenRouter and NVIDIA NIM are configured, with bounded attempts, deadlines, empty-output rejection, provider cooldowns and local request quotas. A request-count quota is not a token-denominated dollar cap, and distributed deployment would need an audit of shared accounting. The smoke script checks for a tool call, not full argument correctness or end-to-end scientific answer truth. No broad locked natural-language result set was found among these artifacts. [Ask route](https://github.com/Lucyyngceo/pyrion/blob/f642df5b9a8279fb613830a924fee97129a3e916/web/app/api/ask/route.ts), [router](https://github.com/Lucyyngceo/pyrion/blob/f642df5b9a8279fb613830a924fee97129a3e916/web/lib/llm/router.ts), [budget](https://github.com/Lucyyngceo/pyrion/blob/f642df5b9a8279fb613830a924fee97129a3e916/web/lib/llm/budget.ts), [smoke script](https://github.com/Lucyyngceo/pyrion/blob/f642df5b9a8279fb613830a924fee97129a3e916/web/scripts/llm-smoke.ts).

One residual universal claim is too strong. A manual trace of `context-check.ts` with target oxygen 34% and the sentence **“The target oxygen is not 34%.”** passes the reviewed lexical/value control flow: `not` is allowed, 34% matches the target, the oxygen token is within the three-token binding window, and no open-axis assertion is made. This negates the target despite the source comment claiming passing sentences can only state target facts. The trace is preserved in `assistant_recount.json`. It is a **synthetic source-reviewed counterexample, NOT RUN against the application**, and does not invalidate deterministic verdicts or measure failure frequency. [Context checker](https://github.com/Lucyyngceo/pyrion/blob/f642df5b9a8279fb613830a924fee97129a3e916/web/lib/context-check.ts).

Separate the language audit from data-validation scope. The latest saved data report, **14 November 17:15:15 UTC**, records 10,003 records, 8,352 traced cells, 933 traced quotes and 3,239 unit rechecks, with **0 BLOCKER, 67 MAJOR, 129 MINOR**. Assistant recount confirms those finding counts. The validation process exits unsuccessfully on blockers, so a passing process is not an all-severity-clean report. Many findings concern conversion parsing or composite values; their existence does not establish that all implicated physics values are wrong. The phase-one claim of closed major AI findings describes a different audit. [Data report](https://github.com/Lucyyngceo/pyrion/blob/f642df5b9a8279fb613830a924fee97129a3e916/validation/reports/latest.json), [validation gate](https://github.com/Lucyyngceo/pyrion/blob/f642df5b9a8279fb613830a924fee97129a3e916/validation/run_all.py).

Its Gaussian-process duration work is a distinct predictive task, beyond IGNIS's current implementation. The source explicitly distinguishes reported burn/test duration from guaranteed extinction time. It uses per-fuel random-row CV and held-out oxygen/pressure blocks, with training-fold standardization. A concrete naming error remains: the random-CV baseline labeled `baseline_rmse_predict_training_mean` uses the whole response vector's mean; the block baseline uses the training subset. This affects baseline interpretation, not evidence of leakage into the GP fit. Small held-out blocks, incomplete interval coverage, omitted diluent/end-type effects and random-row dependence limit transfer claims. The README discusses these limitations. [Model description](https://github.com/Lucyyngceo/pyrion/blob/f642df5b9a8279fb613830a924fee97129a3e916/models/README.md), [CV code](https://github.com/Lucyyngceo/pyrion/blob/f642df5b9a8279fb613830a924fee97129a3e916/models/flex_model.py), [saved metrics](https://github.com/Lucyyngceo/pyrion/blob/f642df5b9a8279fb613830a924fee97129a3e916/data/derived/flex_model.json).

## 5. Flamefall Analytics: the strongest bounded predictive baseline in this review

Flamefall publishes model cards, OOF probabilities and exact split membership, not merely a headline AUC. Its extinction model uses 275 eligible rows from the advertised 276 FLEX burns, with 185 positive extinction labels and 46 saved atmosphere groups. The L2 logistic workflow nests model selection and training-fold preprocessing inside five outer group folds. FLEX groups use gas composition and nominal pressure. This protects against the same atmosphere group appearing in train and test, although shared campaign/apparatus dependence remains. It also publishes separate fuel holdouts. [Model code](https://github.com/ZOGWORK/flamefall-analytics/blob/2af60cb0943243035bcf81edfbd9d326ce0f9f5f/flamefall/model.py), [training script](https://github.com/ZOGWORK/flamefall-analytics/blob/2af60cb0943243035bcf81edfbd9d326ce0f9f5f/scripts/train_models.py), [split artifact](https://github.com/ZOGWORK/flamefall-analytics/blob/2af60cb0943243035bcf81edfbd9d326ce0f9f5f/data/cv_splits.json).

| Model | Saved OOF rows / positive | Grouped AUROC (published 95% interval) | Random-row AUROC | Pooled leave-one-fuel/material-out AUROC | Grouped Brier |
|---|---:|---:|---:|---:|---:|
| Droplet visible-flame extinction | 275 / 185 | .8835 [.8122, .9389] | .8876 | .7444 | .1256 |
| Cool-flame evidence | 47 / 39 | .7532 [.3113, 1.0000] | .9936 | Not available: one fuel | .1210 |
| Solid sustained flame | 179 / 135 | .4806 [.3772, .6526] | .6547 | .5152 | .2720 |

Sources: [extinction card](https://github.com/ZOGWORK/flamefall-analytics/blob/2af60cb0943243035bcf81edfbd9d326ce0f9f5f/data/models/droplet_extinction.json), [cool-flame card](https://github.com/ZOGWORK/flamefall-analytics/blob/2af60cb0943243035bcf81edfbd9d326ce0f9f5f/data/models/droplet_cool_flame.json), [solid card](https://github.com/ZOGWORK/flamefall-analytics/blob/2af60cb0943243035bcf81edfbd9d326ce0f9f5f/data/models/solid_sustained.json). Intervals and fitted outputs are author results, not independently fitted or bootstrapped here.

Assistant pairwise arithmetic reproduces the first two grouped AUCs exactly from saved rounded probabilities. The solid recount is .480808 versus published .480556; allowing rounded ties to order either way gives [.480471, .481145], containing the publication value. This small difference is consistent with probability rounding and is not grounds to call the headline wrong. Brier recounts also agree within rounding. All **15 saved outer folds** have disjoint train/test row IDs and split groups; each test set matches its saved prediction IDs. This is an audit of the supplied membership artifact, not proof that training actually followed it or that source labels are independent and correct.

The unseen-fuel headline needs care: pooled AUROC .7444 combines heptane .6602 (119 rows) and methanol .8098 (156 rows). It is not the worst-fuel result. The cool-flame fall from random-row .9936 to grouped .7532, with a very wide interval, shows why group-level stress tests matter. Published Brier, PR and calibration artifacts are useful additions beyond discrimination alone, but apparent calibration in these folds does not establish calibration for a new atmosphere or fuel. [Extinction card](https://github.com/ZOGWORK/flamefall-analytics/blob/2af60cb0943243035bcf81edfbd9d326ce0f9f5f/data/models/droplet_extinction.json), [cool-flame card](https://github.com/ZOGWORK/flamefall-analytics/blob/2af60cb0943243035bcf81edfbd9d326ce0f9f5f/data/models/droplet_cool_flame.json).

Three additional limits matter for reuse. First, extinction is contrasted with disruption/completion; it is a recorded visible-flame outcome, not a safety classification, and the script supplies an exclusion sensitivity analysis. Second, the Youden threshold is chosen and evaluated using the same pooled OOF predictions: threshold-specific performance needs a separate selection/evaluation layer even though this does not alter AUC. Third, the solid model uses outcome-conditioned oxygen for some rows and assumed pressure for BASS rods; these are unsuitable prospective inputs where the intended task requires pre-outcome conditions or pressure is unreported. The project discloses the limitations and withdraws the solid prediction. Its current model UI labels the failure and suppresses the probability, which deserves credit. [Training/features](https://github.com/ZOGWORK/flamefall-analytics/blob/2af60cb0943243035bcf81edfbd9d326ce0f9f5f/scripts/train_models.py), [threshold code](https://github.com/ZOGWORK/flamefall-analytics/blob/2af60cb0943243035bcf81edfbd9d326ce0f9f5f/flamefall/model.py), [README](https://github.com/ZOGWORK/flamefall-analytics/blob/2af60cb0943243035bcf81edfbd9d326ce0f9f5f/README.md), [model UI](https://github.com/ZOGWORK/flamefall-analytics/blob/2af60cb0943243035bcf81edfbd9d326ce0f9f5f/web/src/app/(console)/models/lab.tsx).

The browser applies stored coefficients without an LLM. This is therefore a stronger comparator for a bounded learned-outcome task, not a generative-answer benchmark. IGNIS cannot claim better predictive accuracy merely because it declines that task. [Browser model implementation](https://github.com/ZOGWORK/flamefall-analytics/blob/2af60cb0943243035bcf81edfbd9d326ce0f9f5f/web/src/lib/model.ts).

## Finite matched evaluation to earn a defensible claim

The following is a proposed **future complementary study, NOT RUN and not a request to start inference**. It must not replace or modify the existing frozen IE-1 packet, scoring or task split; the current authorized evaluation remains on that existing frozen packet. Reading competitors' public questions makes them development material; they cannot subsequently serve as our unseen test set. For the future complementary study, freeze one new 24-case development suite, then a separately reviewed 24-case holdout drawn from different source/experiment families. Record which author or assistant has seen each item. Do not call an assistant reviewer independent human validation.

| Six cases per family in each suite | Required scoring and failure evidence |
|---|---|
| Source field extraction | Exact source/value/unit binding, explicit missingness, quote/page correctness; include mixed units, source conflict and an absent field. Score each cell and the entire record. |
| Evidence Q&A | Correct claim, supporting citation and calibrated abstention; include in-domain unknowns, negation, wrong-case numbers and injection in retrieved data. Evaluate semantic support separately from lexical overlap. |
| Target interpretation | Preserve written oxygen/pressure units and intended cohort; reject invalid/ambiguous targets without defaults. Keep proposed assumptions out of executed requests until accepted. |
| Bounded evidence operations | Reproduce eligible condition sets/frontiers and detector numerator/denominator/missing cells for declared tasks. These are finite computation tests, not physical predictions. |

Use the same permitted source snapshot and task definition for every applicable baseline. Compare deterministic evidence-only behavior, BM25, dense, hybrid and reranked retrieval where supported; compare interpretation configurations only on the same target contract. Preserve each product's native task strengths in a separate capability table rather than forcing a live extractor into a prediction benchmark.
