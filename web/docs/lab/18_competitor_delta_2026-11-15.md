## Consequential source findings

### VESTA: a stronger historical replay package

Its new decision-log format embeds ordered telemetry, scenario metadata, rule/playbook and method terms, plus the complete **normalized** source collection, including unused candidates. The rechecker validates the embedded collection digest and separately compares method, basis and result changes with the current collection. Legacy logs remain explicitly unverifiable. This preserves more historical evidence than an IGNIS recipe-only session; it does not preserve every original NASA binary or certify the science. The documentation correctly distinguishes integrity from authentication and scripted decisions from validated flight software. [Record creation and recheck](https://github.com/itzjk/vesta/blob/605871a0022f27c05ae0b71dc937cf8a00ddf480/web/js/core/replay.js), [documented limits](https://github.com/itzjk/vesta/blob/605871a0022f27c05ae0b71dc937cf8a00ddf480/docs/decision-replay.md).

The new FLEX observation lens requires finite diameter/burn-time pairs, admits oxygen to the 3-D axis only when its basis is ambient, and exposes raw cells, exclusions and source-row identity. It states that rows are not established independent burns and computes no causal effect or uncertainty estimate. This is a useful measurement-exploration workflow; graphics alone do not demonstrate better research decisions. [Observation model and source readout](https://github.com/itzjk/vesta/blob/605871a0022f27c05ae0b71dc937cf8a00ddf480/web/js/world/observation-lens.js).

### PYRION: substantial expansion, with an important coverage-label boundary

The planner evaluates a default 9×9 oxygen/pressure grid using the existing applicability engine, compares hypothetical additions, and ranks geometric coverage gained per proposed test. It explicitly labels nonsourced rectangle-closing corners, grid/tolerance dependence, and hypothetical FM2 cases. The minimum-point construction is a declared geometric convention, not a validated test programme or physical information-gain calculation. These disclosures deserve credit. [Planner implementation](https://github.com/Lucyyngceo/pyrion/blob/914193b93a0330de239797657b5003a42ee36c4b/engine/src/planner.ts).

**Static wording defect:** ERL level 4 says “PSI measured this condition” whenever an investigation is `APPLICABLE`. The engine also assigns that result to an interior point in a tested-condition convex hull, even when no test was performed at that exact point. The label should describe being within the implemented condition envelope. Separately, the material board selects all condition records from any investigation that mentions the material; that is investigation-level relevance, not demonstrated same-material test coverage. These are source-level distinctions, not observed live failures. [ERL mapping and material selection](https://github.com/Lucyyngceo/pyrion/blob/914193b93a0330de239797657b5003a42ee36c4b/engine/src/erl.ts), [hull admission](https://github.com/Lucyyngceo/pyrion/blob/914193b93a0330de239797657b5003a42ee36c4b/engine/src/verdict.ts).

The latest authored data audit now reports **10,077 condition records, zero blocker/major and 134 minor findings**; our finding recount agrees. The earlier 10,022/one-major snapshot is superseded. These are field records and checker findings, not independent experiments or proof of source interpretation. [Latest validation artifact](https://github.com/Lucyyngceo/pyrion/blob/914193b93a0330de239797657b5003a42ee36c4b/validation/reports/latest.json).

## What IGNIS should change as a result

1. **Make the historical-evidence handoff explicit.** VESTA's embedded collection snapshot is a concrete advantage over recipe-only sessions. IGNIS already exports original result bytes separately: make that evidence artifact and the saved recipe one clear review path, showing which object preserves historical results and which recomputes against current data. Do not describe a digest match as independent validation.
2. **Audit the nouns attached to every result.** Keep measured observation, within-envelope condition, metadata mention, hypothetical addition and numeric source match distinct. PYRION's ERL example shows why a correct calculation can still acquire an overstated label. Use adversarial review cases with an unmeasured hull interior, material mentioned elsewhere in an investigation, and a numeric paraphrase that reverses the source meaning.
3. **Demonstrate the existing cutoff workflow before adding another model.** IGNIS's exact fixed-population cutoff/completion certificate answers a bounded question without fitting. Show the source rows, opposite flight-stratum signs, missing-reading bounds, and a wider cutoff rectangle that changes the conclusion; carry the settings through scenario link, saved session and exported evidence. Check that this remains understandable on a narrow screen. Competitors' implementation breadth makes another unsupported prediction module a poor response.

No common blinded task comparison, researcher benefit study, accepted live IGNIS interpretation run, external predictive validation or NASA adoption has been established by this refresh. The useful competitive claim is a precisely demonstrated evidence task, with retained limitations and reproducible artifacts.
