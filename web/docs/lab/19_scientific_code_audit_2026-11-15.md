## Production-only numeric discrepancy caught by the new guard

The first consolidated production build failed at detector admission. Read-only comparison of the actual Turbopack server and browser chunks found **50 distinct numeric cache cells changed among 1,833 matched finite cells in each chunk**, while their original cache strings were preserved. For example:

| Cell | Original string and source JSON number | Bundled numeric token | Binary64 source → bundled |
|---|---|---|---|
| AW23 | 3.6637120000000003 | 3.663712 | `400d4f483cafb3b8` → `400d4f483cafb3b7` |
| BS23 | 0.18182992084451238 | 0.1818299208445124 | `3fc74633edbb10c6` → `3fc74633edbb10c7` |

This is a change of numerical representation, not physical uncertainty. At a cutoff equal to AW23's original value, the source reading satisfies `>=`; the emitted lower value would not. The strict admission guard correctly refused that discrepancy. It must not be replaced by an arbitrary epsilon, and the source JSON must not be edited to resemble the transformed bundle.

`capture_turbopack_numeric_drift.py` and `turbopack_numeric_drift.json` preserve chunk hashes/sizes, exact safe data snippets, original source hash and binary64 comparisons before a rebuild. They do not execute bundle code or claim a specific internal compiler implementation caused the transformation.

**Resolved:** [`package.json`](../../package.json) now explicitly selects the installed Next 16.4.6 version's supported `--webpack` path for both development and production builds. The production build succeeded without weakening the strict detector guard or changing curated data. The new [`source-identity.spec.ts`](../../tests/e2e/source-identity.spec.ts) passed on desktop and mobile Chrome. It compares every exported detector record (154 records), the full conditions and atlas responses, and the catalogue digest with values loaded independently by the offline Node test runner. It also compares the browser-generated cutoff scenario's source digest, result digest and selection with offline `buildResearchAnalysis` output. This checks actual emitted server/browser behavior, beyond merely accepting the source in a unit test.

The original failed build is retained as `_raw/codebase_audit_2026-11-15/production-build-turbopack-failed.log`; the successful Webpack build and the 49-pass/one-skip browser run are recorded in `production-build.log` and `browser-results.json` in that directory. These checks establish identity for the tested source and analysis paths, not a general theorem about every compiler transformation. Subsequent cosmetic notebook-layout changes and their affected UI rerun are tracked separately by root; they do not change this scientific/core checkpoint.

## What the audit did not find

The cutoff-range extrema remain correct for the stated fixed finite population: minimum at `(Amax,Bmin)`, maximum at `(Amin,Bmax)`. The missing-reading completion bounds use the selected-row denominator; paired counts use jointly finite rows. The `{L}` then `(previous,endpoint]` partition correctly retains equality under `>=`, including ties and zero-width domains. No p-value, probability of superiority or physical equivalence follows from those bounds. The changes preserve the default133 paired rows, pooled[66,78]/133 range and opposite flight signs.

Condition comparisons remain within the curated material/burning-side cohort, with pressure and oxygen coordinates only, full original values and publication conflict context. The corpus is frozen and comparisons are detached. No equal-partial-pressure or flow-equivalence inference was found. Frontier missingness strata, finite-input checks and eligibility-by-caller boundaries remain explicit.

The generic frontier's documented final `Number` representation is not an arbitrary-precision comparison theorem. Extremely disproportionate values can collapse distinct exact decimal gaps on conversion. The seven-case condition corpus does not exercise that regime; changing the generic numerical/output contract is not justified by a current product failure. Similarly, an optional richer calibration model or additional statistic is a feature proposal, not a defect repaired by this audit.
