## Reproduced defects and repairs

| Finding | Before | Repaired behavior |
|---|---|---|
| Shared scientific state | In-process callers could modify returned source objects and change later arithmetic while the catalogue digest and assessment ID stayed the same. | Admitted catalogues are frozen; returned assessments and detector analyses are detached. Editing a downloaded file in a separate browser never directly modified server memory; this was an in-process alias defect. |
| Missing definitions passed comparisons | Equal missing units/bases or unknown boundaries could satisfy compatibility. | Required missing definitions remain unknown; documented differences remain contradictions. |
| Ambiguous printed arithmetic | `CO2 mass: 29.9 g` could be parsed as the number 2. A failed computation could still receive a successful-looking scientific conclusion. | Accept a complete, consistent printed decimal/unit only. Unavailable required arithmetic forces an unresolved result with its reason. |
| Unapplied or partial scope | Numeric conditions, text exclusions and some mismatched model/event or multi-quantity requests could look fully handled. | Preserve the requested scope and require clarification where no reviewed evaluator/contract covers it. No invented filtering or new physical transfer rule. |
| Incomplete evidence closure | Selected exports omitted parts of linked lineage, conflicts or definitions. | Follow the finite registered dependency graph, retain linked context and validate typed references, including cycles. This remains selected-analysis evidence, not an exhaustive literature archive. |
| Misleading revision history | Changed qualifications, predicate reasons or reference revisions could be labelled unchanged. | Compare scientific fields and method/source identities. Full before/after wording is available through keyboard-accessible disclosures and both exports. |
| Wrong notebook loaded | A rejected replacement or delayed older file/read response could leave an older notebook's Load action active. | A single operation identity covers file reading, recheck and loading; superseded work cannot replace the latest selection. |
| Stale interpretation completion | An older response/error could reset the status of a newer assessment or loaded notebook. | All operations respect the workspace epoch. Tests use mocked interpretation replies; no provider was called. |
| Invalid revision ancestry | The API accepted inconsistent parent/request ancestry; a checksummed malformed parent could throw; saved histories could fail later import. | Validate comparison fields and visible ancestry before assessment, and complete available notebook ancestry before both saving and loading. A single parent cannot prove uniqueness across unseen ancestors. |
| Incomplete HTTP/checksum boundaries | Limits were checked after full buffering; origin comparison omitted scheme; canonicalization dropped a JSON `__proto__` property. | Bound streamed UTF-8 input, cancel rejected bodies, compare scheme/authority/port, and preserve every JSON property in canonical checksums. Checksums remain unauthenticated. |

## Production numerical identity

The tightened source-text check exposed **50 changed detector values in each inspected Turbopack server/browser chunk**. For example, AW23 changed from `3.6637120000000003` to `3.663712`, while its preserved cache string stayed unchanged. At an exactly equal cutoff this can change the `>=` classification; it is not measurement uncertainty.

Both development and production scripts now explicitly use Next's supported **webpack** path. No epsilon was added and no source value was rewritten. Production tests compare all 154 detector records, complete conditions/atlas exports and the catalogue digest against offline values. They also compare the browser-created cutoff scenario's source/result identities against the offline calculation. Both viewports pass. Historical Turbopack-generated scenario or notebook fingerprints can consequently report drift when reopened; that must remain visible rather than be silently accepted as unchanged.

## Remaining competitive gaps

IGNIS still lacks measured researcher benefit against an equally informed spreadsheet/common competitor tasks, independent source/contract review, accepted live interpretation, a complete historical collection archive in its notebook, and the broader guided planning/new-data workflows of some peers. The current mathematical contribution is an exact finite-data cutoff/completion sensitivity certificate; it is not a physical predictor, calibrated confidence interval or general superiority result.

The strongest demonstration remains one bounded task: inspect the opposite flight-stratum signs, widen the cutoff rectangle, account for unavailable readings, and preserve the exact settings and evidence through revision/export/recheck. Adding an unvalidated predictor would not resolve the remaining evidence gaps. Live inference, new fitting, independent scientific validation, public deployment, submission, outreach and NASA adoption are **NOT RUN or unestablished** in this audit. Existing budget, credential, reuse and release gates remain intact.
